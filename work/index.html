หน้าหลัก/ผลงาน

ระบบที่เราสร้างให้ลูกค้า และที่เราใช้เองจริง

งานที่ไม่ได้จบแค่หน้าจอสวย — ทั้งสองระบบนี้ทำงานอยู่จริง มีคนใช้ทุกวัน และต้องรับมือกับข้อมูลที่ส่งพลาด งานที่ค้าง และการตามแก้เมื่อมีอะไรผิดพลาด

ระบบซิงค์ข้อมูลสาขา → สำนักงานใหญ่ บน Odoo

องค์กรที่มีสาขาจำนวนมาก โดยสาขาใช้ Odoo Community ส่วนสำนักงานใหญ่ใช้ Odoo Enterprise เราพัฒนาโมดูลสองฝั่งให้ส่งข้อมูลหากันผ่าน REST API พร้อมระบบคิว การลองใหม่ และหน้าจอติดตามสถานะ

  • ซิงค์ทั้ง ผู้ติดต่อ/ผู้ขาย สินค้าและหน่วยนับ ใบสั่งซื้อ เอกสารบัญชี การเคลื่อนย้ายสินค้า (รับ/เบิก/โอน) และพนักงาน
  • คิวงานประมวลผลแยก channel นับจำนวนครั้งที่ลองใหม่ และเลื่อนงานที่ยังรอข้อมูลต้นทางไว้ก่อนแทนที่จะปล่อยให้ล้มเหลว
  • หน้า สุขภาพสาขา บอกทันทีว่าสาขาไหนซิงค์ล่าสุดเมื่อไหร่ ค้างหรือล้มเหลวกี่รายการ
  • ฝั่งสาขามีบันทึกการซิงค์รายรายการ เห็นสถานะและข้อผิดพลาดของแต่ละเอกสาร พร้อมหน้าสรุปแยกตามประเภทข้อมูล
  • จัดการ API key สำหรับการเชื่อมต่อ และมีรายการรอแก้ไขให้ตามเก็บงานที่ตกหล่น

DevTrack — ระบบบริหารงานพัฒนาซอฟต์แวร์

ระบบที่เราสร้างขึ้นใช้บริหารงานพัฒนาของตัวเอง รวมการวางแผน ติดตามงาน เก็บความรู้ และเครื่องมือ AI ไว้ในที่เดียว ใช้งานได้ทั้งภาษาไทยและอังกฤษ

  • วางแผนและติดตามงาน — เป้าหมายและผลลัพธ์ (OKR), คัมบัง, แผนภูมิแกนต์, ปฏิทิน, การประชุม, ความต้องการของระบบ และภาระงานรายคน
  • คลังความรู้ในตัว — เอกสาร โน้ต บุ๊กมาร์ก รีไมนเดอร์ และงานตามกำหนดเวลา
  • ระบบเรียนรู้ของทีม — คอร์สเรียนและการฝึกอบรม พร้อมรายงานความคืบหน้า
  • เครื่องมือ AI ที่ควบคุมได้ — ต่อ MCP Servers และ Agent Tools, ค้นหาเว็บ, Embedding และ RAG พร้อมกันข้อมูลส่วนบุคคลตาม PDPA ก่อนส่งออกไปหาโมเดล และดูประวัติกับต้นทุนการใช้งานได้ทุกคำขอ
  • งานผู้ดูแลระบบ — จัดการผู้ใช้ ตั้งค่าอีเมล เข้าสู่ระบบด้วย Google และการเชื่อมต่อกับบริการอื่น

ฝั่ง AI ของระบบ

เรารับงานที่ต้องต่อ AI เข้ากับระบบธุรกิจจริง — ไม่ใช่แค่แปะแชตบอต แต่รวมถึงการคุมค่าใช้จ่าย ตรวจสอบย้อนหลังได้ และกันข้อมูลส่วนบุคคลไม่ให้หลุดออกไปกับคำขอ

ภาพทั้งหมดปิดข้อมูลที่ระบุตัวตนออกแล้ว — ชื่อบริษัท ชื่อสาขาจริง ชื่อบุคคล รูปโปรไฟล์ อีเมล ชื่อโครงการ และที่อยู่ปลายทางของ API ถูกแทนด้วยข้อมูลตัวอย่างทั้งหมด
