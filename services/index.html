ติดตั้งเครื่องแม่ข่าย

ติดตั้งเซิร์ฟเวอร์ให้ โดยคุณเลือกซอฟต์แวร์เอง

เราไม่ผูกลูกค้าไว้กับซอฟต์แวร์ตัวใดตัวหนึ่ง — บอกมาว่าอยากใช้อะไร เราติดตั้งและตั้งค่าให้ใช้งานได้จริง ลงบนเครื่องในองค์กรของคุณเอง หรือบนคลาวด์ที่คุณใช้อยู่ก็ได้ ถ้ายังไม่แน่ใจว่าจะเลือกตัวไหน เราเทียบข้อดีข้อเสียตามงานและขนาดที่คุณใช้จริงให้ก่อนตัดสินใจ และถ้าเป็นซอฟต์แวร์โอเพนซอร์สที่รันบน Linux ต่อให้ไม่มีในรายการนี้ก็ถามมาได้

ประเภทเครื่องแม่ข่าย ตัวเลือกที่รับติดตั้ง สิ่งที่ตั้งค่าให้
เว็บเซิร์ฟเวอร์ nginx · Apache · Lighttpd virtual host หลายโดเมนบนเครื่องเดียว · ใบรับรอง TLS พร้อมต่ออายุอัตโนมัติ · reverse proxy ไปยังแอปหลังบ้าน · HTTP/2 การบีบอัดและแคช · จำกัดอัตราการเรียกและขนาดไฟล์อัปโหลด · หมุนเวียนไฟล์ log
เมลเซิร์ฟเวอร์ Zimbra · Carbonio CE · Stalwart ตั้งโดเมนและกล่องจดหมาย · SPF / DKIM / DMARC ให้เมลออกไม่ตกถังสแปม · ตัวกรองสแปมและไวรัส · เว็บเมลและการเชื่อมต่อ IMAP/SMTP ที่เข้ารหัส · สำรองและกู้คืนกล่องจดหมาย · ย้ายเมลจากระบบเดิม รวมถึงจาก Zimbra ไป Carbonio
ฐานข้อมูล MySQL / MariaDB · PostgreSQL ปรับค่าหน่วยความจำและการเชื่อมต่อตามสเปกเครื่องจริง · แยกผู้ใช้และสิทธิ์ตามระบบงาน · สำรองข้อมูลอัตโนมัติพร้อมทดสอบกู้คืนให้ดู · ตั้งเครื่องสำรอง (replication / standby) เมื่อต้องการ · เปิด log ช้าไว้ตามหางานที่หน่วง
แคชและคิวงาน Redis · Valkey ตั้งเป็นแคชหรือเป็นที่เก็บถาวรตามงานที่ใช้ · จำกัดหน่วยความจำและนโยบายลบข้อมูลเก่า · เปิดรหัสผ่านและ TLS ไม่ปล่อยให้เข้าถึงได้โดยไม่ยืนยันตัวตน · ตั้งโหมดสำรอง (replica / Sentinel) เมื่อระบบทนดับไม่ได้
ที่เก็บอ็อบเจกต์ MinIO · Garage ที่เก็บไฟล์แบบ S3 ไว้ใช้เองในองค์กร · แยก bucket และสิทธิ์ตามระบบงาน · นโยบายอายุไฟล์และการเก็บหลายเวอร์ชัน · ใช้เป็นปลายทางของไฟล์สำรอง · กระจายข้อมูลหลายเครื่องเมื่อต้องการความทนทาน
คอนเทนเนอร์และคลัสเตอร์ Docker & Compose · Docker Swarm · Kubernetes (จัดการผ่าน Rancher) จัดวางบริการเป็นคอนเทนเนอร์ให้ย้ายเครื่องและสร้างซ้ำได้ · วาง registry ภายในองค์กร · ตั้ง ingress และใบรับรอง TLS · กำหนดโควตาทรัพยากรและการรีสตาร์ตอัตโนมัติ · Rancher สำหรับดูและจัดการหลายคลัสเตอร์จากหน้าเดียว พร้อมแยกสิทธิ์ตามทีม
ERP Odoo Community · Odoo Enterprise ติดตั้งพร้อมฐานข้อมูลและ reverse proxy · ตั้งจำนวน worker และ cron ตามจำนวนผู้ใช้ · ติดตั้งโมดูลเสริมและโมดูลที่พัฒนาเอง · ย้ายข้อมูลจากระบบเดิม · วางขั้นตอนอัปเกรดเวอร์ชันโดยมีเครื่องทดสอบก่อนเสมอ
ส่วนประกอบพื้นฐานที่ใช้ร่วมกัน ไฟร์วอลล์ · VPN · ระบบเฝ้าระวังและแจ้งเตือน · ระบบสำรองข้อมูล · รวม log เปิดพอร์ตเท่าที่จำเป็น · ช่องทางเข้าดูแลระบบที่ไม่เปิดสู่อินเทอร์เน็ตตรงๆ · เฝ้าระวังทรัพยากรและบริการพร้อมแจ้งเตือนก่อนล่ม · รวม log ไว้ที่เดียวเพื่อไล่เหตุย้อนหลังได้
อย่างอื่นที่คุณใช้อยู่ ระบบโอเพนซอร์สบน Linux ตัวอื่นๆ รายการข้างบนคือของที่เราทำบ่อย ไม่ใช่ทั้งหมดที่ทำได้ — ถ้าเป็นซอฟต์แวร์โอเพนซอร์สที่รันบน Linux ส่งชื่อมาถามได้เลย เราจะตอบตรงๆ ว่าเคยทำมาก่อนหรือไม่ ต้องใช้เวลาศึกษาเพิ่มเท่าไร และคิดราคาอย่างไร

ทุกงานติดตั้ง ได้สิ่งเหล่านี้เสมอ

  • เอกสารการติดตั้ง — ค่าที่ตั้งไว้จริง พอร์ต ตำแหน่งไฟล์ และบัญชีทั้งหมด ไม่ใช่คู่มือทั่วไปจากอินเทอร์เน็ต
  • สำรองข้อมูลที่กู้คืนได้จริง — เราซ้อมกู้ให้ดูก่อนส่งมอบ ไม่ใช่แค่ตั้ง cron ทิ้งไว้
  • hardening พื้นฐาน — ปิดบริการที่ไม่ได้ใช้ จำกัดการเข้าถึง SSH ตั้งไฟร์วอลล์ และเปิดอัปเดตความปลอดภัย
  • สคริปต์และไฟล์ตั้งค่าที่ใช้ติดตั้ง — ส่งมอบให้ทั้งหมด สร้างเครื่องใหม่ซ้ำได้เอง
  • ส่งมอบสิทธิ์ผู้ดูแลทั้งหมด — เครื่องและข้อมูลเป็นของคุณ ไม่มีบัญชีลับของเราค้างไว้
  • สอนใช้งานให้ทีมของคุณ — งานประจำที่ต้องทำเอง เช่น เพิ่มผู้ใช้ ดูสถานะ และอ่าน log

รับดูแลต่อหลังการติดตั้ง

ติดตั้งเสร็จแล้วจบก็ได้ หรือให้เราดูแลต่อก็ได้ — ขอบเขตการดูแล ช่องทางแจ้งเหตุ และเวลาตอบกลับ ตกลงกันเป็นลายลักษณ์อักษรก่อนเริ่มเสมอ ไม่ใช่รับปากลอยๆ

เฝ้าระวังและแจ้งเตือน

ดูสถานะบริการ พื้นที่ดิสก์ หน่วยความจำ และวันหมดอายุของใบรับรอง แล้วแจ้งก่อนที่มันจะกลายเป็นเรื่อง

อัปเดตและแพตช์ความปลอดภัย

ตามรอบที่ตกลงกัน ทดสอบบนเครื่องทดสอบก่อนเมื่อเป็นการอัปเดตใหญ่ และแจ้งล่วงหน้าถ้าต้องหยุดให้บริการ

ตรวจสอบการสำรองข้อมูล

ดูว่างานสำรองทำงานจริงทุกวัน และซ้อมกู้คืนตามรอบ เพราะไฟล์สำรองที่ไม่เคยกู้ ไม่นับว่ามี

แก้ปัญหาเมื่อมีเหตุ

เข้าดูแลตามช่องทางและกรอบเวลาที่ตกลงไว้ พร้อมสรุปสาเหตุและวิธีกันไม่ให้เกิดซ้ำหลังปิดเหตุ

รายงานประจำงวด

สรุปว่าเดือนที่ผ่านมาเกิดอะไรบ้าง อัปเดตอะไรไป ทรัพยากรเหลือเท่าไร และควรขยายอะไรก่อน

ย้ายเครื่องและขยายระบบ

เมื่อผู้ใช้เพิ่มขึ้นหรือของเดิมเต็ม ช่วยย้ายเครื่อง เพิ่มสเปก หรือแยกบริการออกจากกันโดยกระทบผู้ใช้ให้น้อยที่สุด

เรื่องค่าใช้จ่ายและไลเซนส์ที่ต้องรู้ก่อน

ค่าบริการของเราคือค่าติดตั้ง ตั้งค่า และดูแล — ไม่รวมค่าเครื่อง ค่าคลาวด์ และค่าไลเซนส์ของซอฟต์แวร์เชิงพาณิชย์ เช่น Odoo Enterprise หรือ Zimbra รุ่นที่มีค่าใช้จ่าย ส่วนนี้ลูกค้าซื้อกับผู้ให้บริการโดยตรงและถือสิทธิ์เอง เราช่วยประเมินว่าต้องใช้กี่สิทธิ์และสเปกเท่าไรให้ได้

ถ้าเป็นระบบที่รับผิดชอบข้อมูลส่วนบุคคลหรือเปิดสู่อินเทอร์เน็ต แนะนำให้ดูการออกแบบแบบ Security by Designควบคู่ไปด้วย จะถูกกว่ามาการตามแก้ทีหลัง

วิธีทำงานของเรา

สิ่งที่ติดมากับทุกงาน ไม่ต้องสั่งเพิ่ม

เราถือว่าสี่ข้อนี้เป็นส่วนหนึ่งของงานพัฒนา ไม่ใช่ของเสริมที่คิดเงินแยก

  • เก็บ log และตรวจสอบย้อนหลังได้ — เมื่อระบบมีปัญหา ต้องตอบได้ว่าใครทำอะไรเมื่อไหร่ ไม่ใช่เดา
  • ระบบทนความผิดพลาด — งานที่ส่งไม่สำเร็จต้องเข้าคิวลองใหม่และเห็นสถานะได้ ไม่ใช่หายเงียบ
  • แยกสิทธิ์ตามบทบาท — ผู้ใช้เห็นเฉพาะข้อมูลที่ตัวเองควรเห็น บังคับที่ระดับหลังบ้าน ไม่ใช่แค่ซ่อนปุ่ม
  • ส่งมอบซอร์สโค้ดและเอกสารติดตั้ง — ทีมอื่นรับช่วงต่อได้ ระบบไม่ผูกอยู่กับเรา

ขั้นตอนการทำงาน

เริ่มต้นง่าย ไม่มีค่าใช้จ่ายจนกว่าจะตกลงกัน

คุยความต้องการก่อนเสมอ แล้วค่อยเสนอขอบเขตงานและราคาเป็นลายลักษณ์อักษร

คุยความต้องการ

เล่าปัญหาที่อยากแก้มาได้เลย ยังไม่ต้องมีสเปกละเอียด
